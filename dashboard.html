    Use the buttons like a normal pump switch. Every manual watering is recorded and used to learn the routine. Once a time has been seen on 3 days, Automatic mode can take over.

    Emergency stop
    Switch every pump off now. The Arduino also stops pumps on its own if this page closes or the cable is pulled.

    How the system learns: (1) start times of manual waterings are grouped into time slots (clustering); a slot repeated on 3+ days with a spread under 35 min becomes a learned time. (2) A logistic regression model learns the chance that the farmer waters at a given time, moisture, temperature and light. (3) A KNN classifier checks if the bed behaves like the crop selected in Setup.

    The health score starts at 100 and loses points for soil outside the crop's range, heat or cold stress, pump faults and drying that is unusual compared with what this bed normally does at that hour.

    Smart Irrigation System using Arduino and Machine Learning
    
          
    Problem. Most small farms are watered by hand on fixed timings. Plants get too much water on
            cloudy days and too little on hot ones, pumps are left running when the tank is empty, and if the farmer is away
            nobody waters at all. Fully automatic timers exist but have to be programmed and do not adjust to the crop.
    
          
    Idea. Let the farmer keep working the way they already do. The system watches the manual switching for a few
            days, learns their timings for each bed, and then takes over. While it runs it keeps checking the soil, the weather
            and the pump so it can skip, add or stop a watering, much like a caretaker would.
    

          
    Block diagram
    
          

          
    How one decision is made (every minute)
    
          
      
            
    1. Safety first: stop a pump if moisture has not risen after 5 min (dry run / blocked pipe) or the max run time is reached. A moisture reading stuck at 0 pauses that zone.
      2. 
            
    2. Wilting point: if the soil is below the crop's critical level, water now.
      3. 
            
    3. Learned time: if it is one of the farmer's learned times, water, unless the soil is already moist (e.g. after rain), then skip and log it.
      4. 
            
    4. Model: if the logistic regression gives over 60% chance that the farmer would water now and the soil is below mid-range, water.
      5. 
            
    5. Top-up: if the soil has stayed below the ideal range for 45 min, give a short top-up, but not between 11:00 and 16:00 (evaporation) or at night (fungus).
      6. 
          
    
          
    A watering stops when the target moisture is reached. If the farmer switches the pump by hand it is recorded as a new example, so the schedule keeps following them. If they cancel an automatic watering within 5 minutes, that run is marked as unwanted and not learned.

    Limitations / future work
    
          
      
            
    • The laptop has to stay on for learning and automatic mode. The Arduino only does basic "offline care" without it. An ESP32 with Wi-Fi could host the dashboard instead.
      • 
            
    • Crop check only uses water behaviour. A camera with a leaf disease model would give a real health check.
      • 
            
    • A weather forecast API could skip waterings before expected rain.
      • 
            
    • Data is stored in the browser. A small server database would allow several farms and phones.
